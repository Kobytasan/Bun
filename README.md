# 🥖 Програмний продукт автоматизації каталогу продукції пекарні «Булка»

> **Дипломна робота:** Тестування програмного продукту автоматизації каталогу
> продукції пекарні «Булка»

Електронний каталог продукції пекарні: покупці переглядають асортимент та
оформлюють замовлення, а працівники пекарні ведуть каталог через панель
керування (ціни, склад, наявність, строки свіжості).

## 📄 Сторінки сайту

- `/` — головна (асортимент, «улюблене у покупців», свіже з печі)
- `/catalog` — каталог з категоріями, пошуком та фільтром «лише в наявності»
- `/product/:id` — сторінка виробу (вага, склад, строк свіжості)
- `/cart` — кошик замовлення
- `/checkout` — оформлення (тип покупця: фізособа / кафе / магазин)
- `/order/:id` — статус замовлення за номером
- `/login` — вхід працівників → `/admin` — панель керування

## 🧪 Автоматичні тести (у комплекті)

У проєкті є готовий набір автотестів — 21 перевірка (кошик, замовлення
з датою самовивозу, вхід, права доступу, CRUD каталогу, зняття виробу
з продажу):

```bash
# тест без бази даних (in-memory PostgreSQL)
npm install pg-mem --no-save
node test-local.js   # у першому терміналі — запускає сервер на порту 3001
node test-flow.js    # у другому терміналі — прогоняє всі тест-кейси
```

Кожен рядок `PASS | ...` — це виконаний тест-кейс. Результат можна
вкласти в розділ дипломної роботи «Тестування».

## 🧪 Що перевірити під час тестування

1. Каталог: фільтр категорій, пошук, фільтр «лише в наявності».
2. Кошик: додавання, зміна кількості, видалення позицій.
3. Оформлення замовлення з датою самовивозу → сторінка `/order/:id`.
4. Вхід директора (`director` / `Director2026!`):
   - Огляд: статистика каталогу та замовлень, кількість позицій без запасу;
   - Каталог продукції: додати новий виріб, відредагувати ціну/запас,
     зняти виріб з продажу (⏸) і повернути в продаж (▶), видалити;
   - Замовлення: змінити статус (нове → готується → готово → видано);
   - Працівники: додати новий обліковий запис, видалити.
5. Спробувати зайти під пекарем (`pekar`) — розділ «Каталог продукції»
   буде прихований (перевірка розмежування прав).

## 🚀 Локальний запуск

```bash
npm install
# створіть файл .env за зразком .env.example та вставте DATABASE_URL з Neon
npm start
# відкрийте http://localhost:3000
```

## ☁️ Деплой на Render + Neon

### 1. База даних Neon
1. Зареєструйтесь на [neon.tech](https://neon.tech) → **Create project**.
2. Скопіюйте **Connection string** (вида `postgresql://...neon.tech/neondb?sslmode=require`).

### 2. Сайт на Render
1. Завантажте цю папку в репозиторій GitHub.
2. Render → **New → Web Service** → підключіть репозиторій.
3. Налаштування:
   - **Environment:** Node
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
4. У розділі **Environment Variables** додайте:
   - `DATABASE_URL` = рядок підключення з Neon
   - `SESSION_SECRET` = будь-який довгий рядок
5. Натисніть **Deploy**. При першому запуску таблиці створяться й
   наповняться тестовими даними автоматично.

## 🛠 Технології

- Node.js + Express (SSR, шаблонізатор EJS)
- PostgreSQL (Neon), драйвер `pg`
- Сесії: `express-session`, паролі: `bcryptjs`
- Без фреймворків на клієнті: чисті HTML/CSS/JS
